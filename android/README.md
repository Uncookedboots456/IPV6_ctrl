# IPV6 Ctrl 客户端

源码为 **v2.0 正式版（versionCode 9）**，一个 `dev.ipv6ctrl` APK，配套独立 [Root Runtime](../module/README.md)。联网检测已整合到客户端；不再提供按应用解析控制、LSPosed 依赖、作用域、报告广播或独立探针 APK。

每次点开应用（冷启动或从后台切回）都会自动向 ipify 各查询一次 IPv4 / IPv6 并说明不保存公网 IP；已授权 Root 时同步自动只读系统参数，未授权时显示“授权 Root”主按钮，不会为联网检测等待 Root。首页采用**中心状态圆环 + 双开关卡片**设计：上方圆环与状态标题直报当前模式（`纯 IPv4 模式` / `IPv6 已开启` / `部分开启 IPv6`）与锁定/巡检副标题，点按圆环可直接切换纯 IPv4 模式（右上角提供刷新图标）；下方卡片包含两个独立开关——**“纯 IPv4 模式”开关**（开启调用 `block` 并在已有锁定时保持 `lock`，关闭在有快照时调用 `restore`、无快照时调用 `enable`）与**“锁定”开关**（开启调用 `lock` 实现跨重启持久保持，关闭调用 `pause` 解除锁定），底部为两行常驻“网络连通”状态与图标重测按钮。跨重启锁定与当前实际参数分开判断；锁定结果未知时不会假报已锁定或已解锁。旋转或切主题不会重复请求；默认网络变化或修改系统参数也会触发重测。接口数量、服务状态、仅解除锁定/停止保持、API 详细结果及时间线集中在诊断页分组卡片中，时间线最多保留当前进程的 40 条真实事件。检测区域固定显示 IPv4 / IPv6 两行。检测开始、单个地址族完成、超时、迟到结果丢弃或默认网络变化时，只就地更新该区域的重测图标、spinner、两行结果和提示，不重建整页或 Root 控件；检测占用不会改变 Root 开关的启用条件。导航、主题切换、旋转或 Root 状态需要全页 render 时，等新 `ScrollView` 完成一次 layout 后恢复位置；前一树尚未 layout 时保留待恢复位置，不读取新树的 0，导航不把一个页面的滚动带到另一个页面。状态结果只在真实变化时做约 180ms 的原生短淡入，系统动画关闭或缩放为 0 时即时更新。

## 构建

使用 JDK 21、Android SDK `platforms;android-37.0` 和 `build-tools;36.0.0`。在本地 `local.properties` 配置 `sdk.dir`，或设置 `ANDROID_HOME`。

```sh
cd android
sh tests/system_ipv6_test.sh
./gradlew onlineTest rulesTest :app:assembleDebug :app:lintDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Windows 使用 `gradlew.bat`。没有第三方运行依赖，使用 Android 原生控件与 Java HTTPS API。调试签名不入库。

## 升级与系统控制

旧版曾使用应用策略时，先在旧客户端恢复“跟随系统”，在 LSPosed 停用本模块并清空其作用域，重启目标进程或设备以清除已有 Hook。升级客户端后可卸载旧 `dev.ipv6ctrl.probe`。已发布 v2.0 APK 不能控制新 Runtime，必须使用本分支配套客户端。

安装 Runtime zip 并重启后，首次点击“授权 Root”（或点按首页状态圆环 / 诊断页“刷新”）会授权并读取系统参数；已授权后打开应用会自动只读该系统状态。没有运行中的 Runtime 时主操作保持禁用并说明原因，不会退化为单次写入。Runtime 默认待命；显式禁用时先捕获本次开机的原参数，写入并逐项核对，再记录本次接管目标。每 3 秒读取所有接口并修正漂移，退出客户端不会停止它。

首页“回退到纯 IPv4”（或“重新锁定纯 IPv4”）明确调用 `lock`：除本次接管外，还写入跨重启锁定意图；确认弹窗说明重启后自动保持、仅支持 IPv6 的网络可能断网、修改前设置会先保存可随时恢复。普通快捷磁贴仍调用 `toggle`，关闭只影响本次开机、不新建持久意图；磁贴开启会调用 `enable` 并清除锁定意图。已经“本次 blocked + managed、未持久锁定”的状态可直接升级为持久锁定，沿用本次开机快照。

诊断页“仅解除锁定 / 停止保持”走 `pause`：清除锁定意图并停止本次接管，但保留当前已停用的参数和快照。首页“恢复 IPv6”在有本次开机快照时走 `restore`（先解除锁定，再恢复 `all/default` 与原接口，新增接口恢复为原 `default` 值；失败保留快照且不恢复接管）；若开机自动锁定或磁贴操作导致无本次快照，则提供“开启 IPv6”走 `enable`（清除锁定意图并将各接口设为开启 IPv6），避免有锁却无法在首页退回双栈。控制操作与 worker 共用内核文件锁。重启时有跨重启锁定意图会自动 `adopt`；无意图则默认待命，旧快照与本次目标失效。开机服务最多再拉起 worker 2 次（5s/15s 退避），不会重复自动应用。卸载前请先恢复。

旧版 Runtime 缺少 `desired` / `boot_apply` / `last_sweep_age` 字段，或不支持 `lock` 时，客户端明确提示更新并禁用锁定入口；若旧二进制仍拒绝 `lock`，会显示“不支持跨重启锁定”，不会把仅本次写入当成功。旧 `status` / `pause` / `restore` 协议入口保持兼容。

参数修改会影响全设备及现有连接，IPv6-only 网络可能断网。参数恢复后地址和连接仍需系统重新建立；周期巡检也存在纠偏窗口，切网后请复核。

## 下拉快捷开关 ipv6

客户端提供 Android 原生快捷设置磁贴，名称为 `ipv6`。在诊断页点击“添加 ipv6 到下拉快捷设置”，同意系统提示；也可按下拉面板的编辑或 + 手动添加。Android 9–12 使用手动添加。首次先在客户端点“刷新状态”授予 Root，此后无需保持客户端首页打开；长按磁贴可回到客户端。

| 显示 | 含义与操作 |
| --- | --- |
| 亮起 · 已开启 | 系统允许 IPv6，同时保留 IPv4；点击关闭 IPv6 并保持纯 IPv4。 |
| 亮起 · 部分接口停用 | 当前未接管，各接口状态不同；点击仍会关闭 IPv6。 |
| 熄灭 · 已关闭 | 各接口 IPv6 已停用；点击停止保持并明确开启 IPv6。 |
| 关闭保持中 · 部分接口启用 | 保持目标存在，但读到参数漂移；点击可撤销保持并开启 IPv6。 |
| 锁定未生效 / 保持中断 | 跨重启锁定意图存在但开机应用失败，或本次保持的 worker 已停止；长按进客户端核对，不显示为绿色成功。 |
| 正在读取 / 正在开启 / 正在关闭 | 保留上次确认的亮暗状态，等待期间防止重复操作。 |
| 切换较慢 / 状态未确认 / 切换失败 | 不假报成功；长按进入客户端检查实际状态和错误。 |

默认使用系统网络模式，不自动回退到纯 IPv4。添加磁贴不改变现有配置，也不会为了显示“开”而重置已有关闭目标。磁贴开启走 `enable`，会清除 `desired` 并打开 IPv6，因此已有跨重启锁定时点击点亮就是解锁；磁贴关闭走 `block`，只做本次开机接管，不新建也不清除已有锁定意图。需要保留当前参数解锁时，请在客户端诊断页走 `pause`。每次展开面板和切换完成后读取真实参数；不联网、不在后台轮询。正常点击留在下拉面板，不弹窗、不跳转、不显示成功 Toast；副标题显示切换进度，完成回读后再更新亮暗状态。仅首次未授权 Root 时打开客户端；失败只在磁贴提示并保留错误，长按查看详情。持续保持仍由 Root worker 执行。锁屏点击须通过系统解锁后才能执行。

新快捷切换需要**本次配套 Runtime（协议 v2）**，必须同时更新 APK 与模块。旧协议 v1 仍可从新版客户端读取、暂停及恢复，但快捷切换会明确要求更新，不会静默失败或只改图标。模块更新前先暂停/恢复，按正常安装流程重启；本轮唯一一次真机重启用于新 Runtime 开机接管，不代表磁贴专项已完成验收。

切换在原生控制锁内读取当前状态、决定操作并写入，客户端和磁贴也共享 Java 串行控制。开启 IPv6 会先解除保持，再写入 `0` 并回读，**不会把“恢复快照”误当成“开启”**；原快照仍保留，方便恢复最初设置。关闭时要求 worker 存活，先保存/沿用原快照，再写入 `1` 并接管。短暂锁竞争最多等待约 2 秒，失败保留错误并重新读取，不假报成功。周期纠偏仍有窗口，磁贴不等于所有路径的联网证明。

脚本输入写入也纳入 Root 等待超时。Debug 构建只记录固定操作名、阶段和耗时：Root 使用 `IPV6CtrlRoot`，联网检测使用 `IPV6CtrlOnline`（attempt、family、start/finish/discard/deadline 和相对耗时），便于对照 Root 与网络完成时序；release 不输出这些日志，也不记录脚本内容、URL、IP/网络标识、API 响应或凭据。此前后台切换延迟尚未定位，本次仅完成本地检查，不能视为真机可靠性已验收；按[本轮验收清单](../docs/quick-tile-validation-20261019.md)复测。

实现遵循 [Android 快捷设置文档](https://developer.android.com/develop/ui/views/quicksettings-tiles)。不申请前台服务、通知、写系统设置、无障碍或应用列表权限，不增加第三方运行库。

## 客户端联网检测

打开应用会自动向 [ipify](https://www.ipify.org/) 发起各一次 HTTPS 请求：`api.ipify.org` 检查 IPv4，`api6.ipify.org` 检查 IPv6；界面与时间线会告知该请求且不保存公网 IP。默认网络变化立即使旧结果失效，回到前台合并回调后自动重测；旋转/主题重建、结果仍新鲜时返回前台都不重复请求。整个检测有 15 秒 UI 期限，超时项显示未确认并丢弃迟到结果；不后台轮询、不自动重试、无备用服务。IPv4 / IPv6 两个有界任务独立完成，互不等待；Root 操作仍走原有串行控制，慢检测不锁恢复/暂停。切网时若旧请求仍在等待系统网络超时，重测会在该有界任务结束后开始，不积压新任务。

新增 `ACCESS_NETWORK_STATE` 普通权限用于监听默认网络（无运行时弹窗）；回调随 Activity 生命周期注册/注销，只在客户端进程内保留网络代次。保留 TLS 证书验证，拒绝重定向、过长及错误地址族响应；连接和读取超时各 6 秒，DNS 时间由系统解析器管理。不保存公网 IP，仅在当前客户端进程保留成功标记、错误类型和检测时间。

“巡检已确认”只在阻止目标存在、Runtime 运行、上次巡检 `ok`、状态读取未过期（60 秒内），且把 `last_sweep_age` 加上读取后经过的时间仍不超过 60 秒时显示；`snapshot-error` / `write-error` 显示保持异常，待命、未知巡检或旧 Runtime 缺年龄字段显示待确认。`desired` 未知时单独显示“跨重启锁定未知”，不推断为已锁定或未锁定；`boot_apply=failed/interrupted` 显示锁定未生效，不显示绿色保持；`boot_apply=manual` 表示自动应用曾失败/中断但显式锁定已核实，显示“未自动应用（已手动锁定）”，不冒充开机 adopt 成功。界面展示“上次巡检确认”的真实时刻与年龄，并说明应用没有后台轮询，不能证明两次读取之间始终正常。IPv6 成功说明检测时到 API 的 IPv6 路径可用；IPv4 成功、IPv6 失败不能排除 IPv6 API 自身故障；两者失败则网络/API 原因未确认。禁用 IPv6 也不保证 IPv4 可用；结果需结合系统参数，不等于全设备、所有路径的阻断证明。

## 验证

`onlineTest` 只校验 API 响应字面量、不联网；`rulesTest` 只做纯规则断言（新鲜度、网络代次、巡检年龄、锁定目标、按钮前置条件、全页 render 的滚动保留决策），不执行 Android 生命周期、不访问 Android 或网络，因此不能替代触摸、旋转、快速检测/恢复、切网/动画真机验证。shell 和主机原生测试只使用临时目录。连接 Android 后可执行隔离原生测试（需 Root，禁止写真实 procfs）：

```sh
python tests/run_android_runtime.py --serial DEVICE_SERIAL --ndk-home /path/to/android-ndk-r29
```

该脚本编译独立路径的测试二进制，检查编译路径后才运行；执行前后比较真实参数并清理测试 worker。私密记录存放于忽略的 `android/build/device-debug`。2026-10-26 已通过本次 Android 隔离（真实参数完全不变）、一次新 Runtime 采用明确测试意图的开机接管、客户端 lock/pause/restore、退出保持、新接口纠偏、有限重拉，以及自动检测、旋转/短暂前后台去重、默认网络实际断开/恢复、滚动稳定与检测中立即恢复。动画比例 0 的主题/状态刷新也通过，但未测量帧率。一次重启预算没有覆盖“新客户端设锁后再次重启”的完整链路；磁贴面板、真实 5 分钟停留超时和 IPv6 API 正向路径仍未验证，Runtime 独立 review 为用户选择跳过。详见[本轮记录](../docs/device-validation-20261026.md)；历史回读回滚异常仍未定位，[此前记录](../docs/device-validation-20261017.md)保留，不推送或发布。
