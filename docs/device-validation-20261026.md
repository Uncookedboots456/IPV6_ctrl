# 2.1-dev / code 9：启动检测、持久锁定与交互验收

## 范围和证据边界

本轮在 Android 16 / arm64、KernelSU 兼容 Root 管理器、SELinux Enforcing 的单台设备上验证。客户端与 Runtime 为 versionCode 9，控制协议仍是 `ipv6ctrl-managed-v2`。只使用用户授权的一次重启；没有第二次重启，没有提交、推送或发布。

Grok 完成客户端首轮只读 review，指出滚动恢复问题；Runtime review 连续因模型服务不可用失败后，用户明确选择跳过并直接测试。**Runtime 独立 review 是 waiver，不是通过；功能测试也不等于安全审计。** 后续实现、集成和定点修复由 DeepSeek V4.1 Flash（CC Switch 官方通道，max）完成，主会话执行并核对设备测试。

测试前保存旧 APK、Root 模块、状态文件、修改前快照、接口参数和设置，原始数据仅存忽略的 `android/build/device-debug`，不加入公开仓库。不同 boot 的旧快照只供留档，不可直接恢复到新 boot。

## 已实现

- 打开应用自动进行 IPv4 / IPv6 HTTPS 检测，已授权时同时只读系统状态；旋转和短暂前后台切换复用新鲜结果。新增的普通权限仅 `ACCESS_NETWORK_STATE`。
- 默认网络变化使旧结果失效，前台合并事件后自动重测；Root 操作与两个有界地址族检测独立，不后台轮询、不保存公网 IP。
- 首页明确区分当前接口状态、显式跨重启目标和本次开机应用历史。健康判断结合巡检结果、读取龄期和巡检龄期，未知或失败不显示成功。
- `lock` 显式保存持久意图；开机 `adopt` 在共享控制锁内捕获新 boot 的基线、应用并回读，再启动 worker。`pause` / `enable` / `restore` 清除意图；恢复失败保留快照。
- 自动应用失败/中断后，显式 `lock` 成功才把旧故障记为 `manual`，不冒充自动应用成功；相应失败分支有生产脚本和原生测试。
- 检测只局部更新既有视图，不再重建 Root 按钮或整页；全页重建保留待恢复的滚动位置。状态变化使用约 180ms 的原生淡入，尊重系统动画关闭设置。

## 主机与产物检查

- `onlineTest`、`rulesTest`、APK assemble 和 Android Lint 通过；Lint 为 0 errors / 6 warnings，涉及既有构建/备份配置及 IconView。验证后的源码整回原项目后，主会话在原目录离线重跑上述任务通过，生成 APK 与手机已测试包 SHA-256 完全相同；再顺序重跑 4 个主机 unittest、dash/mksh 自检及 ShellCheck 也全部通过。
- 临时文件中的 Root I/O、原生控制/巡检、持久意图/adopt、有限监督共 4 个 unittest 通过；dash 和 mksh 的生产控制脚本自检、ShellCheck 通过。
- Root I/O 测试使用本地 JVM 子进程替代 `su`；规则断言不执行 Android 生命周期，不能代替真机触摸验证。
- NDK r29 临时重建与随包 Runtime binary 逐字节一致。APK asset 和 zip 内 `control.sh` 与最终源码相同，协议、模块属性、二进制亦核对一致。
- 定点修复测试中曾有一次 WSL `/mnt/c` 的巡检等待超时；后续 4 次隔离单测、3 次完整 discover 通过。该现象未定位，不能用重跑通过消除历史记录。

### 唯一一次重启能证明什么

本轮验证的是**明确预置的持久意图经真实开机服务采用**，不是把测试准备写成客户端行为。客户端 `lock` 的实际持久写入在该次重启后另行验证。

由于新模块需重启激活，未执行完整的“新客户端先 lock → 再次重启 → adopt”端到端链路，也未再重启验证解除锁定后不复活。这些跨 boot 行为有临时 boot_id 的生产脚本/原生回归证据；若需要补齐对应的真机端到端证据，必须另外取得重启授权，不能暗中追加重启。

## 结束状态与恢复边界

断线前最后一次成功检查已恢复测试前的模式：33/33 项禁用，worker 运行，`managed=true`，`desired=none`，仅本次开机持续保持，没有遗留新增的跨重启测试意图；本次新 boot 的恢复快照保留。原快照的旧 boot 留档没有被复制回设备。

Wi-Fi 关闭、蜂窝数据开启，旋转及动画设置还原；未改代理、VPN、DNS、防火墙或其他模块配置。测试接口已删除，采集进程在 finally 中停止。最终尝试刷新首页并清理临时目录前设备再次从 ADB 断开，该次清理命令没有执行，因此本轮唯一的 `/data/local/tmp/ipv6ctrl-acceptance-20261026-081900` 目录可能残留测试 zip/XML/采集 PID 文件，需重新连接后只清理该目录；未将此项计为通过。再次使用跨重启锁定须由用户在客户端明确点击确认。

## 仍未验证 / 已知风险

- 本环境 IPv4 API 成功，IPv6 API 仍无成功正向对照；参数恢复允许时观察到的 global IPv6 地址数为 0。没有通过修改 VPN/DNS 等方式制造成功，API 失败不能单独证明 IPv6 已阻断。
- 旧、新 worker 均观察到蜂窝单接口短暂漂移并随后修正；三秒巡检存在窗口，不是零泄漏方案。变化来源未证明，不归因于某个外部组件。
- 以前重复接管回读失败并回滚的原因未定位；本次通过不冲销旧验收中的异常/隔离参数变化记录。
- 本次设备未添加 `ipv6` 磁贴，没有修改用户快捷设置布局，因此磁贴面板、后台冷启动、锁屏认证的实机流程仍未复测；native toggle 路径仅有隔离证据。
- 未覆盖 Magisk/APatch、Android 9/OEM 广泛兼容、真实卸载恢复、IPv6-only 网络、长时间压力/帧率测试、真实 5 分钟前台超时等待及所有网络/DNS/VPN失败组合。
- 诊断时间线仍在全页 render 时更新；检测区域与检测详情会即时更新，没有宣称时间线也已改为局部实时追加。
