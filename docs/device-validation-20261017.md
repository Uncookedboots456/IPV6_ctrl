# 2.1-dev 真机调试 · 2026-10-17

本轮同时将独立联网探针整合进客户端，移除按应用 Java 解析控制、LSPosed 元数据与依赖、作用域请求和报告广播。最终构建为一个客户端 APK（versionCode 5）及一个 Root Runtime zip；尚未推送或发布。用户要求增加测试和分析后再推送，允许的一次设备重启已用于开机验收。

旧客户端的应用策略先恢复“跟随系统”，本模块在 LSPosed 中停用并清空作用域；升级后旧独立探针已卸载。新 APK 不含 Xposed 元数据。生产 Runtime 二进制在加入条件测试入口后重新构建，仍与原随包二进制逐字节相同。

## 异常与验收边界

1. 首次自动测试并发调用 Root 状态查询与客户端控制，导致 operation-locked。调整测试为等待客户端操作完成后再查询，避免测试自身抢占同一个控制锁。锁冲突仍应作为未完成操作处理，不能视为成功。
2. 一次真实重复接管出现 block-failed-rolled-back：回读未通过，控制器撤销接管并恢复快照。随后三次带跟踪的命令行重复接管，以及包含客户端重复接管的完整流程均通过，尚未定位最初失败的具体节点。不能把后续通过当作该异常已修复。
3. 未运行本 Runtime 时，也观察到蜂窝接口参数发生变化；设备上另一个现有网络组件的脚本同样写入 IPv6 参数。未改动其配置，亦无证据把上述失败归因于特定组件。接口生命周期与并发写入仍需进一步分析。
4. IPv6 参数全部为启用时，IPv6 API 仍解析失败；禁用和恢复后结果相同。尚无该环境下 IPv6 API 成功的正向对照，不能宣称外网 IPv6 阻断已完成全路径验收。
5. 未测试 Magisk / APatch 安装、真实模块卸载恢复、IPv6-only 网络及具体业务应用的消息/通话兼容性。周期纠偏本身存在窗口。

原始参数、网络状态、UI XML、跟踪和 APK 备份仅保存在忽略的本机构建目录，不进入公开仓库。测试完成后 Wi-Fi 关闭、蜂窝开关保持原状；参数已恢复为本轮接管前快照，Runtime 运行但不接管，没有遗留测试目标。

## 首页简化迭代（versionCode 6）

按用户反馈将首页主体改为“回退到纯 IPv4”，只保留回退、恢复、简短状态与网络检测；服务参数、暂停和时间线移入诊断。使用系统 ProgressBar 的独立检测动画，以操作名称区分网络检测和 Root 操作，其余按钮保留原文案并暂时禁用。没有新增运行依赖或 IPv6 模式。

构建、Lint 与 API 响应检查通过。真机检查首页和确认取消、明暗主题、真实检测加载画面、界面重建后的结果与单次请求记录。UI 自动化的无障碍树读取会等待界面静止，短请求可能在读取前已完成，因此加载态使用点击后立即截取的真实屏幕核对，未人为延长请求。此轮不重启、不切换网络或写系统参数，保留设备当时已有的接管目标与快照；上一轮回读回滚及 IPv6 API 正向验证限制仍未消除。
