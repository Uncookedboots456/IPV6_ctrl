# ipv6 面板内切换 · 2026-10-19

本轮按用户选择移除进度 Activity 和弹窗。客户端为 2.1-dev / versionCode 8，配套 Runtime 为协议 v2 / versionCode 8。已有协议 v2 模块无需因本次交互修改再次更新；较早模块仍需使用配套版本。未安装到手机、未改设备参数、未追加重启、未推送或发布，真机测试留待用户稍后进行。

## 当前行为

- 正常点击留在下拉面板，名称始终为 `ipv6`。副标题显示正在开启或关闭，保留上次确认的亮暗状态，重复点击不追加指令。
- Root 控制器在同一锁内读取实际状态并决定方向；回读完成后显示实际参数及保持目标。亮起表示允许 IPv6；关闭并接管表示持续回退纯 IPv4。开关不调用外网 API。
- 超过 10 秒显示“切换较慢 · 等待核对”，继续防止重复操作。Root 输入写入与进程等待共用 30 秒等待期限；错误后再读取实际状态，故整个失败处理可能超过 30 秒。系统冻结进程时界面回调仍可能延迟。
- 成功无弹窗、跳页或 Toast。失败以磁贴文案提示，并保留错误供长按查看；仅首次尚未准备 Root 授权时打开客户端。
- 面板重新展开会重新读取；进程内未完成操作不自动重试。持续保持仍由现有独立 Root worker 执行，没有新增 Android 常驻服务、权限或第三方库。

## 本地检查

APK 构建、Android Lint、API 响应校验、shell 临时文件检查及主机 Runtime 联测通过。新增 `tests/test_root_io.py` 使用本机 JVM 子进程模拟 Root 输出和输入管道堵塞，验证写入等待可超时、错误不会误判成功、旧协议提示及非法操作拒绝；不执行 su，不写真实系统参数。需要 JDK，运行 `python -m unittest discover -s tests -p test_root_io.py -v`。

Root I/O 测试仅替换外部进程与等待时长，其余使用当前生产类代码。它不模拟 Android 后台冻结、KernelSU 调度或手机 ROM 行为。

## 尚未完成的真机验收

1. 先记录实际模式、worker、当前开机和快照；客户端刷新成功后展开面板，核对显示与实际参数一致。
2. 实际点击双向切换，确认面板不收起、不出现进度页，完成后亮暗与全部接口及保持目标一致。记录耗时，不以图标变化代替参数核对。
3. 连续点击确认只执行一次；切换中收起并重新展开面板，确认不重复切换且最终状态正确。
4. 收起面板、结束本客户端进程后重新展开，核对 Root worker 仍存活，再测试双向切换。应用“强制停止”可能受系统停用规则影响，应与普通清后台分别记录。
5. 验证失败提示、长按进入客户端及主页面同步；旧联网检测结果应标记需重测。锁屏操作仍须系统认证，不绕过解锁。
6. 测试结束保留/恢复测试前模式和原快照，并还原任何临时亮屏设置。不要清除已有快照或修改其他网络组件。

Debug 日志只输出固定操作名、阶段和耗时：

```sh
adb -s DEVICE_SERIAL logcat -v threadtime -s IPV6CtrlTile:D IPV6CtrlRoot:D '*:S'
```

关注 `start` → `spawned` → `input-sent` → `exited` → `finished`，区分 Root 启动、输入传输、执行及客户端回调延迟。私密原始日志和 UI 记录仅留忽略的 `android/build/device-debug`。

## 历史证据边界

10 月 17 日原生添加、单次切换、客户端同步及连续点击防重复有通过记录，但后台冷启动出现过长期“切换中”。短时前台服务和 TileService 对话框试验也未完全消除延迟；暂停前安装的进度 Activity 方案未完成验收，本轮已移除。不能把这些结果当作当前无窗口方案已通过。

协议 v2 的两次 Android 临时目录测试均完成各功能组，但外层真实参数前后比较失败，观察到蜂窝接口变化；因此不计为整体隔离测试通过，亦未证明变化由哪个组件引起。v2 采用备份后热更新验证，没有追加完整手机重启；此前一次开机验收属于更早版本。

此前一次重复接管回读失败并回滚的原因仍未定位，IPv6 API 仍无启用状态下成功的正向对照；见[此前验收记录](device-validation-20261017.md)。本轮修改不宣称解决这些问题。
